01

useState

React Hooks

What is it?

Manage local state.

🧠 Layman example

A counter app needs to remember its current number. useState gives the component a value to remember and a setter to request a new value.

When / why would you use it?

Use it when a component owns changing UI data such as a counter, selected tab, input value, modal visibility, or toggle.

Practical example

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}

Intern questions

1. What problem does useState solve that a normal local JavaScript variable does not solve in a React component?
How to approach / expected direction

Look for the connection between persistent component data, rendering, and React's state update mechanism.

2. If a button should increase a counter twice from the current value, what state-update pattern should you investigate and why?
How to approach / expected direction

The intern should recognize that updates depending on previous state may need the previous-state/function form rather than repeatedly using a captured value.

02

useEffect

React Hooks

What is it?

Synchronize a component with an external system.

🧠 Layman example

Think of a room's light being synchronized with a real electrical switch outside the room. The React render describes UI; an effect is used when the component must coordinate with something outside that rendering process.

When / why would you use it?

Use it for synchronization such as subscriptions, timers, browser APIs, network connections, or other external systems—not simply because some code needs to run.

Practical example

import { useEffect } from "react";

function OnlineStatus() {
  useEffect(() => {
    function handleOnline() {
      console.log("Online");
    }

    window.addEventListener("online", handleOnline);

    return () => {
      window.removeEventListener("online", handleOnline);
    };
  }, []);

  return <p>Listening for connection changes</p>;
}

Intern questions

1. A developer puts every API call inside useEffect. What question should they ask before deciding an effect is appropriate?
How to approach / expected direction

The guide frames effects as synchronization with external systems. Look for that distinction instead of treating useEffect as a general lifecycle replacement.

2. Why does the event-listener example return a cleanup function? What resource is being managed?
How to approach / expected direction

The cleanup removes the subscription so the component does not leave an obsolete listener behind.

useContext

React Hooks

What is it?

Read values supplied by React Context.

🧠 Layman example

Imagine a company-wide notice board. Instead of passing the same notice through every manager to every employee, people can read it from the shared board.

When / why would you use it?

Use it when a value needs to be available to many components in a subtree, such as theme or authentication information, without manually passing it through every level.

Practical example

import { createContext, useContext } from "react";

const ThemeContext = createContext("light");

function Button() {
  const theme = useContext(ThemeContext);

  return <button data-theme={theme}>Save</button>;
}

How to approach / expected direction

Look for awareness that context consumers can react to context-value changes and that context is not automatically a universal state-management solution.

04

useRef

React Hooks

What is it?

Store mutable values or reference DOM elements without causing renders.

🧠 Layman example

Think of a drawer where you keep a small note. You can change the note without asking the whole room to be redrawn.

When / why would you use it?

Use it for DOM references, timers/IDs, previous values, or mutable information that must survive renders but should not itself trigger a render.

Practical example

import { useRef } from "react";

function SearchBox() {
  const inputRef = useRef(null);

  function focusInput() {
    inputRef.current?.focus();
  }

  return (
    <>
      <input ref={inputRef} />
      <button onClick={focusInput}>Focus</button>
    </>
  );
}

Intern questions

1. Why would a ref be preferable to state when you need to remember a timer ID but do not need the timer ID displayed?
How to approach / expected direction

The key distinction is persistence across renders without causing a render when the value changes.

2. Why is inputRef.current useful in the example, and why would putting the DOM node in state be an awkward design?
How to approach / expected direction

The ref provides access to the DOM node. State is intended for data whose changes participate in rendering.

05

useReducer

React Hooks

What is it?

Manage more structured state transitions.

🧠 Layman example

Imagine a bank counter. Instead of randomly changing the account balance, you give the system an action such as deposit or withdraw, and a reducer determines the next state.

When / why would you use it?

Use it when local state has several related values or many state transitions that are easier to describe as actions and a reducer.

Practical example

import { useReducer } from "react";

function reducer(state, action) {
  switch (action.type) {
    case "increment":
      return { count: state.count + 1 };
    case "reset":
      return { count: 0 };
    default:
      return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });

  return (
    <button onClick={() => dispatch({ type: "increment" })}>
      {state.count}
    </button>
  );
}

Intern questions

1. What is the responsibility of the reducer compared with dispatch?
How to approach / expected direction

Look for reducer = calculates next state; dispatch = sends an action describing what happened.

2. What characteristics of a component's state would make you consider useReducer instead of several independent useState calls?
How to approach / expected direction

The intern should discuss structured transitions, related state and many action types rather than simply saying useReducer is 'better'.

06

useMemo

React Hooks

What is it?

Memoize expensive calculated values when appropriate.

🧠 Layman example

Suppose calculating a large report takes time. If the inputs have not changed, you may want to reuse the previous calculation instead of doing the same work again.

When / why would you use it?

Use it when a calculation is meaningfully expensive and its dependencies often remain unchanged; optimization should be justified by the actual rendering situation.

Practical example

import { useMemo } from "react";

function ProductList({ products, query }) {
  const filtered = useMemo(
    () => products.filter(p =>
      p.name.toLowerCase().includes(query.toLowerCase())
    ),
    [products, query]
  );

  return filtered.map(p => <p key={p.id}>{p.name}</p>);
}

Intern questions

1. Why is useMemo not something you should automatically add to every calculated value?
How to approach / expected direction

The guide describes useMemo as caching calculations when appropriate; the intern should connect it with actual cost and dependency changes.

2. What determines when the filtered calculation above is allowed to reuse its previous result?
How to approach / expected direction

The dependency values determine when React needs to recalculate the memoized value.

07

useCallback

React Hooks

What is it?

Memoize function references when useful for rendering optimization.

🧠 Layman example

Imagine giving someone the same contact card instead of printing a new card every time you talk to them. The important part is that the identity of the function reference can remain stable when appropriate.

When / why would you use it?

Use it when function identity matters—for example, when passing a callback to a memoized child or when a hook depends on a function reference.

Practical example

import { useCallback, useState } from "react";

function Parent() {
  const [count, setCount] = useState(0);

  const handleSave = useCallback(() => {
    console.log("Saved");
  }, []);

  return (
    <>
      <button onClick={() => setCount(c => c + 1)}>
        {count}
      </button>
      <Child onSave={handleSave} />
    </>
  );
}

Intern questions

1. What is useCallback actually remembering: the result of a function or the function reference?
How to approach / expected direction

The expected distinction is function identity/reference versus the function's returned result.

2. Why might useCallback provide no meaningful benefit if the child component is going to render anyway?
How to approach / expected direction

Look for an understanding that memoization is useful only when stable identity changes rendering behavior or dependency behavior.

08

useLayoutEffect

React Hooks

What is it?

Run an effect synchronously after DOM mutations and before paint.

🧠 Layman example

Imagine measuring a picture frame and adjusting it before the customer sees it on the wall. The measurement/update needs to happen before the visible paint to avoid a noticeable intermediate state.

When / why would you use it?

Use it for rare DOM measurement/layout work where timing before paint matters. Prefer useEffect for normal synchronization.

Practical example

import { useLayoutEffect, useRef } from "react";

function Tooltip() {
  const ref = useRef(null);

  useLayoutEffect(() => {
    const rect = ref.current?.getBoundingClientRect();
    console.log(rect);
  }, []);

  return <div ref={ref}>Tooltip</div>;
}

Intern questions

1. Why might measuring an element in useLayoutEffect be different from measuring it in useEffect?
How to approach / expected direction

The intern should focus on timing relative to DOM mutations and browser paint.

2. Why should useLayoutEffect not automatically replace useEffect for ordinary side effects?
How to approach / expected direction

Look for the fact that layout effects are intended for layout-sensitive work, while ordinary external synchronization generally belongs in useEffect.

useImperativeHandle

React Hooks

What is it?

Customize what a parent receives through a ref.

🧠 Layman example

Imagine a device that exposes only three safe buttons to the outside instead of exposing its entire internal machinery. The parent receives a controlled interface.

When / why would you use it?

Use it for carefully designed imperative component APIs—for example, a custom input exposing focus or a limited action to its parent.

Practical example

import {
  forwardRef,
  useImperativeHandle,
  useRef
} from "react";

const SearchInput = forwardRef(function SearchInput(props, ref) {
  const inputRef = useRef(null);

  useImperativeHandle(ref, () => ({
    focus() {
      inputRef.current?.focus();
    }
  }));

  return <input ref={inputRef} />;
});

Intern questions

1. Why might exposing a small method such as focus() be preferable to exposing the entire internal DOM structure?
How to approach / expected direction

Look for encapsulation: the parent receives a deliberate imperative API instead of internal implementation details.

2. What does useImperativeHandle change about the value available through the parent's ref?
How to approach / expected direction

The hook customizes the ref's exposed handle.

useTransition

React Hooks

What is it?

Mark updates as non-urgent transitions.

🧠 Layman example

Imagine a receptionist handling an urgent phone call while also preparing a report. The urgent response should remain responsive while the report can be processed as lower priority work.

When / why would you use it?

Use it when a UI update may be expensive and should not block more urgent interactions such as typing or clicking.

Practical example

import { useState, useTransition } from "react";

function Search() {
  const [query, setQuery] = useState("");
  const [isPending, startTransition] = useTransition();

  function handleChange(e) {
    const value = e.target.value;
    setQuery(value);

    startTransition(() => {
      // Update expensive results here
    });
  }

  return <input value={query} onChange={handleChange} />;
}

How to approach / expected direction

2. Why could marking an expensive update as non-urgent improve the experience of a search interface?
How to approach / expected direction

Look for urgent input responsiveness being separated from less-urgent rendering work.

useDeferredValue

React Hooks

What is it?

Defer a value to keep urgent UI responsive.

🧠 Layman example

Imagine a search box where the letters you type should appear immediately, while a large result list can catch up slightly later.

When / why would you use it?

Use it when a value is expensive to consume and you want urgent parts of the interface to remain responsive while the slower UI catches up.

Practical example

import { useDeferredValue, useState } from "react";

function SearchResults({ products }) {
  const [query, setQuery] = useState("");
  const deferredQuery = useDeferredValue(query);

  const results = products.filter(product =>
    product.name.includes(deferredQuery)
  );

  return (
    <>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <Results items={results} />
    </>
  );
}

1. What is the difference in responsibility between the immediate query and the deferred query?
How to approach / expected direction

The intern should identify the immediate value as the urgent input and the deferred value as a lower-priority version consumed by expensive UI.

2. What kind of UI problem is useDeferredValue intended to improve?
How to approach / expected direction

Look for responsiveness under rendering pressure, not network-delay management.

Hook composition

React Hooks

What is it?

Combine hooks to create higher-level reusable behavior.

🧠 Layman example

Instead of building one huge machine, combine smaller machines that each perform one job. A custom hook can compose useState, useEffect, useRef and other hooks into one reusable behavior.

When / why would you use it?

Use hook composition when a feature requires several related behaviors and the combination itself is reusable.

Practical example

function useSearch(query) {
  const [results, setResults] = useState([]);

  useEffect(() => {
    // fetch/search based on query
  }, [query]);

  return results;
}

function SearchPage() {
  const results = useSearch("react");
  return <Results items={results} />;
}

Intern questions

1. Why can composing several smaller hooks be easier to reuse than copying the same hook calls into many components?
How to approach / expected direction

Look for abstraction: the custom hook exposes the useful behavior while hiding implementation details.

2. If useSearch internally used state, an effect and a ref, what would the consuming component need to know about those internal details?
How to approach / expected direction

The consumer generally uses the custom hook's public return value/API rather than managing every internal hook itself.

Rules of Hooks

React Hooks

What is it?

Learn where and how hooks may legally be called.

🧠 Layman example

Think of a railway switch system: it must follow a predictable order so the system knows which track corresponds to which train. Hooks rely on consistent call order.

When / why would you use it?

Call hooks at the top level of React function components or custom hooks, not inside conditions, loops or nested functions.

Practical example

function Profile({ loggedIn }) {
  const [name, setName] = useState("");

  if (!loggedIn) {
    return <p>Please log in</p>;
  }

  // Do not conditionally call another hook here.
  return <p>{name}</p>;
}

Intern questions

1. Why would calling a hook conditionally make React's hook state tracking unreliable?
How to approach / expected direction

The intern should connect the rule with consistent hook call order across renders.

2. A developer writes a hook inside an if statement because it 'only needs to run sometimes.' What should they investigate as an alternative design?
How to approach / expected direction

Look for moving the condition inside the hook's logic, restructuring the component, or splitting components so the hook itself is called consistently.
