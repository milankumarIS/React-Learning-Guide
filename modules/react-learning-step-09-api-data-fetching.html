01API & DATA

Fetch API

Use the browser's native HTTP client.

What is it?

Fetch is built into browsers and sends HTTP requests, returning a Promise for a Response.

🧠 Layman analogy

Like calling a delivery service directly instead of hiring an intermediary.

When / why use it?

Use it for browser requests when native APIs meet your needs; remember HTTP error statuses do not automatically reject the promise.

Practical example

async function loadUsers() {
  const response = await fetch("/api/users");
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

Research questions

  1. Why should code check response.ok before treating a response as successful?
  2. What does response.json() return, and why is it asynchronous?
How to approach / expected answer direction

Trace the request, Response, status check, and body parsing. Research network errors versus HTTP error statuses.

Explain the reasoning and trade-offs in your own words. Verify implementation details against the official documentation for your chosen API or library.

Mini task

Fetch a list of users and display loading, success, and failure states.

22API & DATA

Request cancellation

Cancel obsolete network requests.

What is it?

Cancellation stops or ignores work that is no longer relevant, such as an old search request after the query changes.

🧠 Layman analogy

Like cancelling an outdated delivery order after the destination changes.

When / why use it?

Use for component cleanup, fast-changing searches, and preventing stale requests from wasting work.

Practical example

useEffect(() => {
  const controller = new AbortController();
  fetch(`/api/search?q=${encodeURIComponent(query)}`, {
    signal: controller.signal
  }).then(r => r.json()).then(setResults)
   .catch(error => {
     if (error.name !== "AbortError") setError("Search failed");
   });
  return () => controller.abort();
}, [query]);

Research questions

  1. How does AbortController communicate cancellation to fetch?
  2. Why should an expected abort not always be shown as a user-facing error?
How to approach / expected answer direction

Trace a query changing from 're' to 'react' and explain how the earlier request is prevented from winning.

Explain the reasoning and trade-offs in your own words. Verify implementation details against the official documentation for your chosen API or library.
