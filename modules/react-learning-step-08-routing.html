02ROUTING

React Router

Learn the standard routing ecosystem for React.

What is it?

React Router maps URL paths to components and provides navigation tools and route data hooks.

🧠 Layman analogy

It is the building directory that tells visitors which room matches each sign.

When / why use it?

Use it when different URLs should display different pages or layouts.

Practical example

import { BrowserRouter, Routes, Route } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}

06ROUTING

08ROUTING

14ROUTING

useSearchParams

Read and modify URL search parameters.

What is it?

useSearchParams returns the current query parameters and a setter for updating them.

🧠 Layman analogy

It lets you read and edit the options written on a delivery slip.

When / why use it?

Use for filters, search terms, sort order, and pagination that should survive refreshes and be shareable.

Practical example

const [searchParams, setSearchParams] = useSearchParams();
const sort = searchParams.get("sort") ?? "newest";

function chooseSort(value) {
  setSearchParams(prev => {
    prev.set("sort", value);
    return prev;
  });
}

15ROUTING

Protected routes

Restrict routes based on authentication or permissions.

What is it?

A protected route checks whether the current user may access a page and redirects or displays an alternative when access is denied.

🧠 Layman analogy

A keycard-controlled door checks permission before opening.

When / why use it?

Use for account pages, dashboards, and restricted tools, while remembering frontend checks are not a substitute for backend authorization.

Practical example

function RequireAuth({ children }) {
  const { user, loading } = useAuth();

  if (loading) return <p>Checking session…</p>;
  if (!user) return <Navigate to="/login" replace />;
  return children;
}

19ROUTING

Lazy-loaded routes

Load route code only when needed.

What is it?

Lazy-loaded routes defer downloading a page component until the app needs it, which can reduce initial JavaScript cost.

🧠 Layman analogy

A library brings a book from storage only when a visitor requests it.

When / why use it?

Use for larger pages or sections that are not needed on the initial screen; pair with a loading fallback.

Practical example

import { lazy, Suspense } from "react";

const Reports = lazy(() => import("./Reports"));

<Suspense fallback={<p>Loading reports…</p>}>
  <Routes>
    <Route path="/reports" element={<Reports />} />
  </Routes>
</Suspense>

Research questions

  1. What is the trade-off between initial bundle size and loading a route later?
  2. What does Suspense display while a lazy component is loading?
How to approach / expected answer direction

Your answer should explain the reasoning and trade-offs in your own words. Verify details against the official React Router documentation.
