01

What is state?

State & Component Logic

What is it?

State is data that belongs to a component and can change over time. A state change can cause React to render the component again so the UI reflects the current state.

🧠 Layman example

Think of a light switch. The current state is ON or OFF. When the state changes, what you see changes too.

When / why would you use it?

Use state for information that can change during the lifetime of the UI and should affect what is displayed or how the component behaves.

Practical example

function Counter() {
  const [count, setCount] = useState(0);

  return <button onClick={() => setCount(count + 1)}>
    Count: {count}
  </button>;
}

2. If a value changes but the UI does not need to react to the change, should it automatically become state? Explain your reasoning.
How to approach / expected direction

The intern should consider whether the value participates in the rendered UI or component behavior rather than storing everything in state.

02

useState

State & Component Logic

What is it?

useState is the primary React Hook for adding local state to a function component. It gives the component a current value and a setter used to request an update.

🧠 Layman example

Imagine a notebook with a current score written on it. You read the score and use a controlled way to write the new score when something happens.

When / why would you use it?

Use it for simple local values such as counters, input values, toggles, selected tabs, modal visibility and small UI state.

Practical example

import { useState } from "react";

function Toggle() {
  const [open, setOpen] = useState(false);

  return (
    <button onClick={() => setOpen(!open)}>
      {open ? "Close" : "Open"}
    </button>
  );
}

How to approach / expected direction

The answer should identify the state value and setter function.

2. Why does calling the setter matter more than directly changing the variable returned by useState?
How to approach / expected direction

Look for React's update mechanism and the idea that direct reassignment does not correctly request a React state update.

03

State updates

State & Component Logic

What is it?

A state setter requests a state update. React may schedule and batch updates, then render the component using the resulting state.

🧠 Layman example

Think of placing several orders at a restaurant. The kitchen can group the work rather than immediately preparing every single instruction independently.

When / why would you use it?

Use normal state setters whenever the user interaction or logic needs the UI to reflect new state.

Practical example

const [count, setCount] = useState(0);

function handleClick() {
  setCount(count + 1);
  setCount(count + 1);
}

Intern questions

1. Why might the two setCount calls above not produce the result a beginner expects?
How to approach / expected direction

The key idea is that updates may be batched and the captured value may be the same for both calls.

2. What should you investigate when several state updates depend on the same current state value?
How to approach / expected direction

This leads naturally to functional state updates when the next value depends on the previous one.

04

Functional state updates

State & Component Logic

What is it?

A functional state update gives the setter a function that receives the previous state and calculates the next state. It is useful when the next value depends on the previous value.

🧠 Layman example

Imagine saying, “Take whatever score is currently on the board and add one,” rather than saying, “Take the score I saw five minutes ago and add one.”

When / why would you use it?

Use it when multiple updates may happen together or whenever the next state is calculated from the previous state.

Practical example

function handleClick() {
  setCount(prevCount => prevCount + 1);
  setCount(prevCount => prevCount + 1);
}

Intern questions

1. Why is prevCount safer than using count directly when the new value depends on the old value?
How to approach / expected direction

The intern should understand that React supplies the latest pending state to the updater function.

2. How would you rewrite an update that adds an item to an array when several updates could happen close together?
How to approach / expected direction

For arrays, the same principle is used: derive the next array from the previous array rather than relying on a potentially stale captured value.

05

State immutability

State & Component Logic

What is it?

React state should be updated without mutating the existing object or array. Instead, create a new value representing the updated state.

🧠 Layman example

Think of an official document. Instead of secretly changing the old signed copy, create an updated copy so everyone can clearly identify the new version.

When / why would you use it?

Use immutable updates for objects, arrays and nested state so changes are explicit and React can reliably detect new references.

Practical example

const [user, setUser] = useState({
  name: "Milan",
  role: "Intern"
});

setUser({
  ...user,
  role: "Developer"
});

Intern questions

1. What is the difference between changing user.role directly and creating a new object with the updated role?
How to approach / expected direction

Look for new object/reference creation instead of modifying the existing state value.

2. Why is immutability especially important when state contains arrays or objects?
How to approach / expected direction

The intern should connect immutable updates with predictable change detection, debugging and avoiding accidental shared mutations.

Updating objects in state

State & Component Logic

What is it?

To update an object in state, create a new object and copy the properties that should remain unchanged, then override the property being changed.

🧠 Layman example

Imagine filling out a new form version: you copy the existing information and change only the field that needs correction.

When / why would you use it?

Use this whenever state is an object containing several related values.

Practical example

const [profile, setProfile] = useState({
  name: "Riya",
  city: "Bhubaneswar"
});

setProfile(prev => ({
  ...prev,
  city: "Cuttack"
}));

07

Updating arrays in state

State & Component Logic

What is it?

Arrays in state should be replaced with a new array when adding, removing or changing items. Common tools include map, filter and spread.

🧠 Layman example

Think of a shopping list. You make a new version of the list when adding or removing an item instead of secretly editing the original shared list.

When / why would you use it?

Use immutable array operations for lists such as todos, products, users, selected IDs and cart items.

Practical example

const [todos, setTodos] = useState([]);

function addTodo(todo) {
  setTodos(prev => [...prev, todo]);
}

function removeTodo(id) {
  setTodos(prev => prev.filter(todo => todo.id !== id));
}

Intern questions

1. How would you add one item without mutating the previous array?
How to approach / expected direction

Look for a new array created with spread or another immutable approach.

2. Which array method would you consider for removing items based on an ID, and what should its callback return?
How to approach / expected direction

filter is the natural concept to investigate for producing an array without matching items.

08

Derived state

State & Component Logic

What is it?

Derived state is information that can be calculated from existing props or state. It often does not need its own state variable.

🧠 Layman example

If you already know the price and quantity, the total bill is a calculation—not another notebook value that must be separately maintained.

When / why would you use it?

Prefer calculating values during rendering when they can be reliably derived from existing data instead of duplicating them in state.

Practical example

const [price, setPrice] = useState(100);
const [quantity, setQuantity] = useState(2);

const total = price * quantity;

Intern questions

1. Why can storing total separately from price and quantity create a consistency problem?

2. How would you decide whether a value should be stored in state or calculated from existing state?
How to approach / expected direction

Look for a rule based on whether the value can be calculated from existing reactive inputs without needing independent updates.

09

Lifting state up

State & Component Logic

What is it?

Lifting state up means moving shared state to the closest common parent of components that need to coordinate around it.

🧠 Layman example

Two siblings cannot directly own one shared notebook. Their common parent can hold the notebook and pass the relevant information down.

When / why would you use it?

Use this when sibling components need to stay synchronized and local state in one sibling cannot cleanly control the other.

Practical example

function Parent() {
  const [selectedId, setSelectedId] = useState(null);

  return (
    <>
      <List selectedId={selectedId} onSelect={setSelectedId} />
      <Details selectedId={selectedId} />
    </>
  );
}

Intern questions

1. Why is the common parent often the right place for state shared by two siblings?
How to approach / expected direction

Look for one source of truth and coordinated sibling behavior.

2. What signals that state may need to be lifted instead of duplicated in both child components?
How to approach / expected direction

The intern should identify duplicated state that can drift out of sync as a reason to lift it.

Sharing state between components

State & Component Logic

What is it?

Components can coordinate by sharing state through a common parent, context or an external state solution depending on scope and complexity.

🧠 Layman example

Imagine several people needing the same notice board. If only two people need it, their team lead may manage it. If an entire office needs it, a shared central board may make more sense.

When / why would you use it?

Choose the simplest sharing mechanism that fits the number of consumers and the distance between them in the component tree.

Practical example

function App() {
  const [theme, setTheme] = useState("light");

  return (
    <Page theme={theme} onThemeChange={setTheme} />
  );
}

How to approach / expected direction

The expected reasoning should emphasize keeping state as local as practical and avoiding unnecessary complexity.

Controlled components

State & Component Logic

What is it?

A controlled component is an input whose value is driven by React state. React becomes the source of truth for the current input value.

🧠 Layman example

Think of a form where a receptionist records every change in the official register. The displayed value and the register stay synchronized.

When / why would you use it?

Use controlled inputs when you need validation, conditional UI, instant feedback, or direct access to the current form value.

Practical example

function NameForm() {
  const [name, setName] = useState("");

  return (
    <input
      value={name}
      onChange={e => setName(e.target.value)}
    />
  );
}

Intern questions

1. What is the source of truth for the input value in this example?
How to approach / expected direction

The answer should identify React state as the source of truth.

2. Why are controlled inputs useful when a form needs live validation or conditional UI?
How to approach / expected direction

Look for the ability to inspect and react to each value change.

12

Uncontrolled components

State & Component Logic

What is it?

An uncontrolled component lets the DOM maintain the current input value, with React accessing it when needed, commonly through a ref.

🧠 Layman example

Instead of the receptionist recording every keystroke, the customer fills the form and the receptionist reads the final value when required.

When / why would you use it?

Use uncontrolled inputs when direct DOM-managed values are sufficient, particularly for some simple forms or integrations where the DOM is the natural owner.

Practical example

function SimpleForm() {
  const inputRef = useRef(null);

  function handleSubmit(e) {
    e.preventDefault();
    console.log(inputRef.current.value);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} />
      <button>Submit</button>
    </form>
  );
}

Intern questions

1. Who maintains the current value of an uncontrolled input?
How to approach / expected direction

The intern should identify the DOM as the owner of the input value.

2. What role does a ref play in accessing the value at submission time?
How to approach / expected direction

The ref provides access to the underlying DOM node so its current value can be read.

Component state vs application state

State & Component Logic

What is it?

Local component state is usually concerned with one component or feature area. Application state is shared information that multiple distant parts of an application need.

🧠 Layman example

A desk has its own notebook, while the company has information that many departments need. Not every piece of information belongs in the company-wide system.

When / why would you use it?

Keep UI-only state local when possible; consider shared/application state when many unrelated areas need the same source of truth.

Practical example

// Local UI state
const [isModalOpen, setIsModalOpen] = useState(false);

// Potential shared application state
const currentUser = /* shared authentication state */;

Intern questions

1. Why might modal visibility remain local while authenticated-user information is shared?
How to approach / expected direction

The distinction should be based on who needs the information and its scope.

2. What questions would you ask before moving local state into a global store?
How to approach / expected direction

Look for consumer count, ownership, synchronization needs and complexity rather than “global is always better.”

State colocation

State & Component Logic

What is it?

State colocation means keeping state close to the components that actually use it instead of moving every piece of state to a high-level parent.

🧠 Layman example

Keep your keys near the door rather than placing every household item in one central cupboard. Put things where they are naturally used.

When / why would you use it?

Use colocation to reduce prop drilling, unnecessary rerenders and large components that own unrelated state.

Practical example

function SearchPanel() {
  const [query, setQuery] = useState("");

  return (
    <input
      value={query}
      onChange={e => setQuery(e.target.value)}
    />
  );
}

Intern questions

1. What problems can appear when unrelated state is moved into a very high-level component?
How to approach / expected direction

Look for unnecessary parent complexity and wider-than-needed update scope.

2. How does keeping search state inside SearchPanel improve ownership and maintainability?
How to approach / expected direction

The intern should connect local ownership with simpler component APIs and clearer responsibilities.

State initialization

State & Component Logic

What is it?

State can be initialized with a direct initial value or, when calculating the initial value is expensive, a lazy initializer function.

🧠 Layman example

Imagine opening a file cabinet. If finding the initial document takes effort, you would rather perform that search only when the cabinet is first opened rather than every time you look at the cabinet.

When / why would you use it?

Use direct initialization for simple values. Consider lazy initialization when the initial calculation itself is expensive.

Practical example

const [count, setCount] = useState(0);

const [items, setItems] = useState(() => {
  return createInitialItems();

Preserving and resetting state

State & Component Logic

What is it?

React can preserve state when it considers a component to have the same identity. Changing component identity or using keys intentionally can cause state to reset.

🧠 Layman example

Think of a student keeping the same notebook when they remain in the same class. If the student is replaced by a different identity, a fresh notebook may be appropriate.

When / why would you use it?

Understand this when switching views, rendering components conditionally, resetting forms and using keys to intentionally reset component state.

Practical example

function App({ userId }) {
  return <ProfileForm key={userId} userId={userId} />;
}
