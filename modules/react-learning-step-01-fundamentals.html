01

What is React?

React Fundamentals

What is it?

React is a JavaScript library for building user interfaces from reusable components. You describe the UI for the current data/state and React handles the necessary UI updates.

🧠 Layman example

Think of a menu made from reusable cards: one card design can be used for every dish.

Proper use case

Use it when an application has many interactive screens and repeated UI patterns such as dashboards or e-commerce pages.

Practical example

function Welcome({ name }) { return <h1>Hello, {name}</h1>; }

Intern questions

1. What problem is React trying to solve compared with manually changing DOM elements?
Expected direction / how to evaluate

Mention UI complexity, reusable components, declarative rendering and easier updates.

2. If a dashboard has 50 similar cards, what advantage does a component-based approach give you?
Expected direction / how to evaluate

Explain reuse: one component can represent a repeated pattern while different data is supplied through props/state.

SPA vs traditional web applications

React Fundamentals

What is it?

A traditional multi-page application commonly requests a new document during navigation. A SPA changes the visible application UI on the client without a full document reload for every navigation.

🧠 Layman example

A traditional site is like leaving one shop and entering another; a SPA is like staying in one mall while moving between departments.

Proper use case

Admin dashboards and rich web applications often benefit from client-side navigation because the application shell can remain in place.

Practical example

function App(){const [page,setPage]=React.useState('home');return <>{page==='home'?<Home/>:<Orders/>}</>}

React Fundamentals

Event propagation

React Fundamentals

What is it?

Events can propagate through nested elements. Understanding bubbling, capturing and stopping propagation helps prevent unexpected parent handlers.

🧠 Layman example

A bell inside a room inside a building can be noticed by the small area and then by larger containing areas unless propagation is stopped.

Proper use case

Important for nested clickable UI such as cards containing buttons, menus and dialogs.

Practical example

function Card(){return <div onClick={()=>console.log('card')}><button onClick={e=>{e.stopPropagation();console.log('delete')}}>Delete</button></div>}

Intern questions

1. Why might the Card handler also run when Delete is clicked?
Expected direction / how to evaluate

Explain bubbling from the target toward ancestors.

2. When is stopping propagation useful, and when might it hide a deeper event-design problem?
Expected direction / how to evaluate

Mention intentional nested interactions while avoiding stopPropagation everywhere as a substitute for clear event design.
