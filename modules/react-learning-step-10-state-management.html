01STATE MGMT

Local state

Use component-level state for isolated UI concerns.

What is it?

Local state belongs to a component and tracks values that affect that component's UI.

🧠 Layman analogy

A notepad kept at one desk rather than shared across the whole office.

When / why use it?

Use for toggles, open/closed menus, input values, and small pieces of UI state used in one area.

Practical example

const [isOpen, setIsOpen] = useState(false);
return <button onClick={() => setIsOpen(v => !v)}>
  {isOpen ? "Close" : "Open"}
</button>;

Research questions

  1. What clues suggest a value should stay local instead of becoming global state?
  2. What can go wrong when unrelated components share a single state container?
How to approach / expected answer direction

Identify which components need the value and choose the narrowest owner that supports the required behavior.

02STATE MGMT

useReducer

Model structured local state transitions.

What is it?

useReducer stores state and updates it through a reducer function that receives the current state and an action.

🧠 Layman analogy

A clerk follows a fixed set of rules to update a record based on a submitted action.

When / why use it?

Use when state transitions are related, structured, or easier to reason about as named actions.

Practical example

function reducer(state, action) {
  switch (action.type) {
    case "increment": return { count: state.count + 1 };
    case "reset": return { count: 0 };
    default: return state;
  }
}
const [state, dispatch] = useReducer(reducer, { count: 0 });

Research questions

  1. When might useReducer be clearer than multiple useState calls?
  2. Why should a reducer calculate next state rather than perform network requests or other side effects?
How to approach / expected answer direction

Map each action to its input state and returned next state; look for pure, testable transitions.

Explain the reasoning and trade-offs in your own words. Library APIs and maintenance status can change; verify current details in official documentation before choosing a tool.

Zustand

Research a lightweight external state store.

What is it?

Zustand is a state-management library that exposes a store and lets components subscribe to selected state values.

🧠 Layman analogy

When / why use it?

Practical example

  const count = useCounter(s => s.count);

08STATE MGMT

Jotai

Research atom-based state management.

What is it?

Jotai models state as small atoms that components can read and update, allowing state to be composed from focused units.

🧠 Layman analogy

When / why use it?

Practical example

  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;

12STATE MGMT

Reducers

Calculate next state from current state and an action.

What is it?

A reducer is a function that decides the next state from the current state and an action.

🧠 Layman analogy

When / why use it?

Use for predictable, testable state transitions, especially with useReducer or Redux.

Practical example

function counterReducer(state, action) {
  if (action.type === "increment") return state + 1;
  if (action.type === "reset") return 0;
  return state;
}

16STATE MGMT

createSlice

Define Redux Toolkit state, reducers, and actions together.

What is it?

createSlice groups a slice's initial state and reducer case functions, and generates action creators.

🧠 Layman analogy

When / why use it?

Use to organize Redux state by feature and reduce hand-written action/reducer boilerplate.

Practical example

import { createSlice } from "@reduxjs/toolkit";

const cartSlice = createSlice({
  name: "cart",
  initialState: { count: 0 },
  reducers: {
    itemAdded(state) { state.count += 1; }
  }
});
export const { itemAdded } = cartSlice.actions;
