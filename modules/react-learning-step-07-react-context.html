01CONTEXT

Creating context

Define shared values for a component subtree.

What is it?

Create a context when distant components need the same value without manually passing it through every intermediate component.

🧠 Layman example

Like a shared notice board that people in the same department can read.

When / why use it?

Use for shared theme, locale, or auth information when it fits the component tree.

Practical example
import { createContext } from 'react';
export const ThemeContext = createContext('light');

02CONTEXT

Provider

Supply a context value to descendants.

What is it?

A provider wraps a subtree and makes a value available to consumers below it. The nearest matching provider supplies the value.

🧠 Layman example

A manager places a notice board in a department; people in that area can read it.

When / why use it?

Wrap only the subtree that should receive the value.

Practical example
<ThemeContext.Provider value="dark">
  <AppContent />
</ThemeContext.Provider>

03CONTEXT

useContext

Read context values.

What is it?

useContext reads the value from the nearest provider for a context. It is a hook and must follow the Rules of Hooks.

🧠 Layman example

A team member reads the department notice board instead of asking every manager to pass along the message.

When / why use it?

Use inside a component or custom hook that needs the value.

Practical example
const theme = useContext(ThemeContext);
return <main className={theme}>...</main>;

04CONTEXT

Context consumers

Understand how components consume context.

What is it?

A consumer is a component that reads a context value, commonly through useContext. Consumers update when the context value they use changes.

🧠 Layman example

Any staff member who reads the shared board is a consumer of that board.

When / why use it?

Keep consumers focused on the values they actually need.

Practical example
function ThemeLabel() {
 const theme = useContext(ThemeContext);
 return <span>Theme: {theme}</span>;
}

05CONTEXT

Context composition

Combine multiple contexts cleanly.

What is it?

Apps may need separate contexts for theme, authentication, locale, or other concerns. Composition means arranging providers clearly.

🧠 Layman example

A company has separate notice boards for HR, IT, and announcements instead of one giant board.

When / why use it?

Separate unrelated concerns and keep provider nesting understandable.

Practical example
<ThemeProvider>
  <AuthProvider>
    <App />
  </AuthProvider>
</ThemeProvider>

06CONTEXT

Context performance

Understand rerenders caused by changing context values.

What is it?

Consumers can rerender when a provider value changes. Frequently changing or broad values may cause extra rendering work.

🧠 Layman example

If a board changes every minute, everyone watching it may need to check for updates.

When / why use it?

Measure before optimizing; keep values appropriately scoped and stable where useful.

Practical example
const value = useMemo(() => ({ user, signOut }), [user, signOut]);
<AuthContext.Provider value={value}>{children}</AuthContext.Provider>

07CONTEXT

Context for themes

Use context for application-wide theme information.

What is it?

Theme context can expose shared theme settings such as light/dark mode or design tokens to many components.

🧠 Layman example

A building's lighting setting applies to many rooms without each room needing a separate instruction.

When / why use it?

Use when multiple distant components must respond to a theme change.

Practical example
const theme = useContext(ThemeContext);
return <div data-theme={theme}>{children}</div>;

08CONTEXT

Context for authentication

Share current user/auth state.

What is it?

An authentication context may expose the current user and authentication-related actions to components that need them.

🧠 Layman example

A building access desk confirms whether a person is signed in so different rooms can tailor what they show.

When / why use it?

Use to share UI auth state; backend authorization must still protect data and actions.

Practical example
const { user, signOut } = useContext(AuthContext);
return user ? <Profile /> : <LoginPrompt />;

09CONTEXT

Context vs Redux

Compare context with dedicated state management.

What is it?

Context shares values through the React tree. Redux is a dedicated state-management approach with its own store and update patterns.

🧠 Layman example

A shared notice board is not the same as a full record system with history and workflows.

When / why use it?

Compare complexity, debugging needs, update patterns, and team familiarity.

Practical example
// Context
const settings = useContext(SettingsContext);

// Redux-style selector
const count = useSelector(state => state.counter.value);

10CONTEXT

Context vs Zustand

Compare context with lightweight external stores.

What is it?

Context shares values through the React tree. Zustand is a lightweight external store often used for shared state and selector-based subscriptions.

🧠 Layman example

Context is a department notice board; an external store is a service different teams can query.

When / why use it?

Compare state ownership, subscriptions, ergonomics, and app complexity.

Practical example
// Zustand-style example
const count = useCounterStore(state => state.count);
