Component Communication

This module turns the fifth section of the React intern guide into a practical learning worksheet. The focus is how components exchange information, where state should live, and how props, callbacks, Context and composition create clear communication boundaries.

01

Parent → Child communication

Component Communication

What is it?

A parent component sends information to a child through props. The child receives the values and uses them while rendering or handling events.

🧠 Layman example

Think of a manager giving an employee an instruction sheet. The employee can use the information, but the manager remains the owner of the instruction.

When / why would you use it?

Use props when the parent owns the data and the child only needs to display it or use it to perform its job.

Practical example

function Parent() {
  const user = { name: "Milan", role: "Developer" };

  return <Profile user={user} />;
}

function Profile({ user }) {
  return <h2>{user.name} — {user.role}</h2>;
}

1. Who owns the user object in this example, and how does the child receive it?
How to approach / expected direction

Look for one-way parent-to-child data flow through props.

2. If Profile needs another value from its parent, what is the normal React mechanism for passing it?
How to approach / expected direction

The intern should identify props as the normal communication boundary.

02

Child → Parent communication

Component Communication

What is it?

A child normally communicates an event or result to its parent by calling a callback function supplied through props.

🧠 Layman example

Imagine an employee reporting, “The task is complete.” The manager supplied the reporting process, while the employee triggers it when something happens.

When / why would you use it?

Use callback props when a child interaction needs to cause the parent to update state or perform an action.

Practical example

function Parent() {
  const [selected, setSelected] = useState(null);

  return (
    <Child onSelect={id => setSelected(id)} />
  );
}

function Child({ onSelect }) {
  return <button onClick={() => onSelect(42)}>Select</button>;
}

Intern questions

1. Why does the parent pass a function instead of letting the child directly modify the parent's state?
How to approach / expected direction

Look for ownership: the parent owns its state and exposes a controlled way to request an update.

2. What happens to the data flow when Child calls onSelect(42)?
How to approach / expected direction

The callback carries an event/value from child back to logic owned by the parent.

03

Sibling communication

Component Communication

What is it?

Siblings do not normally update one another's state directly. Shared state is commonly moved to their nearest common parent, which passes data and callbacks down.

🧠 Layman example

Two coworkers need the same information. Instead of secretly editing each other's notebooks, their team lead keeps the shared record and communicates the relevant pieces.

When / why would you use it?

Use this when two sibling components need to stay synchronized.

Practical example

function Parent() {
  const [value, setValue] = useState("");

  return (
    <>
      <Input value={value} onChange={setValue} />
      <Preview value={value} />
    </>
  );
}

Intern questions

1. Why can the common parent be a better owner of state used by two siblings?
How to approach / expected direction

Look for one source of truth and coordination through the parent.

2. What problem can occur if both siblings keep separate copies of the same shared value?
How to approach / expected direction

The copies can become inconsistent or require awkward synchronization.

04

Prop drilling

Component Communication

What is it?

Prop drilling means passing data through intermediate components that do not actually need the data, only so a deeper component can receive it.

🧠 Layman example

Imagine passing a message through five people when only the fifth person needs it. The middle people become messengers rather than participants.

When / why would you use it?

Use direct props when the tree is shallow; consider composition, Context or an appropriate shared-state solution when repeated deep passing becomes a real problem.

Practical example

function App({ user }) {
  return <Layout user={user} />;
}

function Layout({ user }) {
  return <Sidebar user={user} />;
}

function Sidebar({ user }) {
  return <UserMenu user={user} />;
}

Intern questions

1. Why can prop drilling make a component tree harder to maintain?
How to approach / expected direction

The issue is not passing props itself; it is unnecessary intermediate plumbing and growing coupling.

2. Should every chain of two or three props automatically be replaced with Context? Why or why not?
How to approach / expected direction

A good answer balances simplicity: props are often preferable for local, explicit relationships.

05

Context for communication

Component Communication

What is it?

Context allows a value to be made available to descendants without passing it manually through every intermediate component.

🧠 Layman example

Think of a building-wide notice board. People on different floors can access the same information without every floor manager forwarding it.

When / why would you use it?

Use Context when many descendants need the same value and prop passing becomes cumbersome, such as theme, locale or authentication information.

Practical example

const UserContext = createContext(null);

function App() {
  return (
    <UserContext.Provider value={{ name: "Milan" }}>
      <Dashboard />
    </UserContext.Provider>
  );
}

function Profile() {
  const user = useContext(UserContext);
  return <p>{user.name}</p>;
}

Intern questions

1. What problem does Context solve compared with passing user through every intermediate component?
How to approach / expected direction

Look for reducing intermediate prop plumbing.

2. Why is Context not automatically the best solution for every shared value?
How to approach / expected direction

The intern should consider scope, coupling and whether ordinary props or another state solution would be simpler.

06

Callbacks as communication contracts

Component Communication

What is it?

A callback prop can define a clear contract: the child reports that something happened and supplies the information the parent needs.

🧠 Layman example

A delivery worker follows a predefined reporting format instead of directly changing the company's internal records.

When / why would you use it?

Use callbacks to keep ownership of state and business decisions in the appropriate parent while allowing reusable children to report events.

Practical example

function SearchInput({ onSearch }) {
  return (
    <input
      onChange={e => onSearch(e.target.value)}
      placeholder="Search"
    />
  );
}

function Page() {
  function handleSearch(query) {
    console.log("Search:", query);
  }

  return <SearchInput onSearch={handleSearch} />;
}

Intern questions

1. What makes onSearch a useful API for a reusable SearchInput?
How to approach / expected direction

Look for a small, intention-based API rather than exposing parent implementation details.

2. Why should SearchInput avoid knowing how the parent will store or process the query?
How to approach / expected direction

The child should report the event/value; the parent decides what the event means for its feature.

07

Composition

Component Communication

What is it?

Composition means building larger components by combining smaller components and allowing callers to provide pieces of UI.

🧠 Layman example

A house is assembled from rooms and furniture rather than becoming one giant inseparable object.

When / why would you use it?

Use composition for layouts, cards, dialogs, pages and reusable containers.

Practical example

function Card({ children, footer }) {
  return (
    <section className="card">
      <div>{children}</div>
      <footer>{footer}</footer>
    </section>
  );
}

<Card footer={<button>Save</button>}>
  <h2>Profile</h2>
  <p>User details</p>
</Card>

Intern questions

1. How does children make Card more reusable than hardcoding a specific body?
How to approach / expected direction

Look for structure/layout being owned by Card while content is supplied by the caller.

2. What responsibility should Card own, and what responsibility should its caller own?
How to approach / expected direction

The caller controls content; the container controls the surrounding structure and behavior.

08

Render props

Component Communication

What is it?

A render prop is a prop whose value is a function that a component calls to determine what UI to render or what data to expose.

🧠 Layman example

Think of a service provider that supplies information, while the customer decides how that information should be presented.

When / why would you use it?

Use this pattern when a reusable component owns behavior or data but consumers need control over the rendered UI. In modern React, custom hooks often solve many of the same problems more simply.

Practical example

function MouseTracker({ render }) {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  return render(position);
}

<MouseTracker
  render={({ x, y }) => <p>{x}, {y}</p>}
/>

Intern questions

1. What does MouseTracker own and what does the caller control?
How to approach / expected direction

The reusable component owns behavior/state; the render function controls presentation.

2. Why might a custom hook be considered instead of a render prop in modern React code?
How to approach / expected direction

Look for simpler separation of reusable logic from UI through hooks.

09

Higher-Order Components (HOC)

Component Communication

What is it?

A Higher-Order Component is a function that takes a component and returns an enhanced component.

🧠 Layman example

Think of a service wrapper around an existing machine: the machine remains the core device, while the wrapper adds capability.

When / why would you use it?

Use HOCs when working with existing libraries or architectures that use component enhancement. They are less common for new code where hooks and composition may be clearer.

Practical example

function withLoading(Component) {
  return function WithLoading({ loading, ...props }) {
    if (loading) return <p>Loading...</p>;
    return <Component {...props} />;
  };
}

const UserListWithLoading = withLoading(UserList);

Intern questions

1. What does a HOC receive and what does it return?
How to approach / expected direction

Look for component-in/component-out enhancement.

2. What potential complexity can appear when many HOCs wrap the same component?
How to approach / expected direction

The intern may identify wrapper nesting, prop tracing and debugging/display-name complexity as possible costs.

10

Compound components

Component Communication

What is it?

Compound components are a group of components designed to work together around shared state or an implicit coordination API.

🧠 Layman example

Think of a tab system: Tabs, TabList, Tab and TabPanel are separate pieces, but together they form one coordinated control.

When / why would you use it?

Use them when a component has multiple related subcomponents and you want consumers to compose the structure while the system coordinates behavior.

Practical example

<Tabs>
  <Tabs.List>
    <Tabs.Tab value="profile">Profile</Tabs.Tab>
    <Tabs.Tab value="settings">Settings</Tabs.Tab>
  </Tabs.List>

  <Tabs.Panel value="profile">Profile content</Tabs.Panel>
  <Tabs.Panel value="settings">Settings content</Tabs.Panel>
</Tabs>

Intern questions

1. Why can compound components be more flexible than a component with dozens of configuration props?
How to approach / expected direction

Look for flexible composition and a coordinated component family.

2. What shared information might Tabs internally coordinate between Tab and TabPanel?
How to approach / expected direction

The intern should think about active tab state, registration/selection and relationships between subcomponents.

Context vs props

Component Communication

What is it?

Props make data flow explicit between a parent and child. Context provides implicit access to a value for descendants that opt into the context.

🧠 Layman example

Props are like a person handing you a document directly. Context is like accessing a shared notice board.

When / why would you use it?

Use props for explicit local relationships and Context when many descendants need the same value without repeated intermediate passing.

Practical example

// Explicit
<Profile user={user} />

// Context
<UserContext.Provider value={user}>
  <DeepTree />
</UserContext.Provider>

Intern questions

1. What makes props easier to trace than Context in a simple parent-child relationship?
How to approach / expected direction

Props visibly document the data boundary in the component call.

2. What signs might indicate that Context is more appropriate than adding another long prop chain?
How to approach / expected direction

Repeated deep passing to many descendants is a common signal to consider Context.

12

Global state vs Context

Component Communication

What is it?

Context is a delivery mechanism for values through a component tree; it does not by itself provide all the behavior of a complete global state-management architecture.

🧠 Layman example

A company notice board can distribute information, but it is not automatically the company's complete accounting system.

When / why would you use it?

Use Context for suitable shared values; use a dedicated state-management approach when application state has complex updates, selectors, persistence, debugging or other requirements.

Practical example

// Context can expose a shared value:
const AuthContext = createContext(null);

// A more complex application store may have
// its own update and subscription architecture.

Intern questions

1. Why is saying 'Context is global state management' an oversimplification?
How to approach / expected direction

The intern should distinguish value distribution from state architecture.

2. What requirements might make a dedicated state-management solution worth considering?
How to approach / expected direction

Look for complexity, update patterns, selectors, persistence, tooling or many consumers as possible considerations.

13

Communication design and ownership

Component Communication

What is it?

Good component communication starts by deciding who should own the state and what public interface other components should use.

🧠 Layman example

A company works better when ownership is clear: one department owns the record while others submit requests through defined processes.

When / why would you use it?

Use the simplest ownership model: keep state local when possible, lift it when siblings need it, use Context for appropriate deep shared values, and use external state when the application's complexity justifies it.

Practical example

function SearchPage() {
  const [query, setQuery] = useState("");

  return (
    <>
      <SearchInput value={query} onChange={setQuery} />
      <Results query={query} />
    </>
  );
}

Intern questions

1. Before choosing Context or a global store, what questions should you ask about ownership and consumers?
How to approach / expected direction

Look for scope, number of consumers, update frequency, coupling and complexity.

2. How would you explain the difference between 'where state lives' and 'how components communicate about it'?
How to approach / expected direction

State ownership is about who controls the source of truth; communication is about the interface through which components exchange information.
